Repository README

A guide from aligned reads to biological interpretation

Developmental chromatin changes.
What does Bap1 loss do to them?

This pipeline analyzes mm10 CUT&RUN data for total H2AZ, H2AZac and H2AZub across early and late development, in controls and Bap1 cKO. It measures changes at shared genomic loci, summarizes combinations across marks, and follows normally developmentally regulated loci into the cKO.

This guide describes the implemented analysis, not a set of biological results. The updated figure step has been exercised on synthetic data; real-data conclusions require your samples and locus review.

1 · PurposeTwo views of the same loci

At sites that normally gain or lose H2A.Z-related signal during development, how often does Bap1 loss change that signal—and in which direction?

Development-anchored responses

Choose loci using late versus early controls. Keep those locus identities fixed, then examine early and late cKO effects in each mark. This is the primary view for the original biological question.

Joint-state summaries

Within each contrast, combine the three marks’ increase/decrease/no-detected-change calls. This describes coordinated patterns among loci with at least one detected change in that contrast.

Anchor mark means the mark used to select the developmental cohort. Response mark means the mark examined after selection. For example, H2AZub-gain loci can be examined for cKO effects in H2AZub itself, H2AZac or total H2AZ. All nine anchor/response combinations are included.

The pipeline does not require a developmental site to be responsive to cKO before including it. Keeping sites with no detected cKO change is essential to a meaningful response frequency.

2 · DesignFour groups, three marks

All four groups are required for each of H2AZ, H2AZac and H2AZub, with at least two independent biological replicates per mark/group. That is at least 24 antibody libraries in the complete design, not necessarily 24 different animals: the same animal can contribute different marks.

The five modeled comparisons
ComparisonDirectionQuestion
Control developmentLC − ECWhat normally changes with development? Defines the anchor cohorts.
Early cKO effectEK − ECWhat differs after Bap1 loss at the early stage?
Late cKO effectLK − LCWhat differs after Bap1 loss at the late stage?
cKO developmentLK − EKWhat changes with development in cKO?
Stage × genotype interaction(LK − EK) − (LC − EC)Does the developmental change differ between genotypes?

The formulas denote contrasts on the modeled log scale, not subtraction of raw read counts. The outputs report log2 fold changes (LFCs), uncertainty and adjusted P values.

3 · MethodFrom BAM files to fixed-locus comparisons

  1. Validate the inventory

    Run three self-tests, then check the sample sheet, BAM/index paths, required groups, replicate counts, optional metadata and whether batch can be estimated separately from group. Excluded rows do not enter the analysis.

    scripts/01_validate_inventory.R

  2. Reuse peaks or call missing ones

    Supplied peaks are reused. Missing paired-end peaks use SEACR; missing single-end peaks use MACS3. Peak calls are made per replicate. SEACR without IgG uses the top 1% of signal blocks, an exploratory threshold—not an FDR.

    scripts/02_call_peaks.sh

  3. Build one master locus set

    Require support from at least two replicates within each mark/group, then union those supported regions across strata, merging overlaps. Remove blacklist overlaps and keep chr1–chr19 and chrX. Save stable locus IDs and use the same regions for every mark and comparison.

    scripts/03_build_master_regions.R

  4. Count, normalize and model each mark

    DiffBind counts reads over the master loci without control subtraction. DESeq2 models four groups; an estimable multi-level batch adds a batch term (~ Tissue + Condition in DiffBind metadata), otherwise the design is ~ Condition. Five contrasts produce per-locus effects and state calls. Each mark has its own analysis.

    scripts/04_diffbind_per_mark.R

  5. Follow normal developmental cohorts into cKO

    Control-development + loci form a gain cohort; - loci form a loss cohort. Join every cohort locus to all three response marks. Count cKO responses, load saved normalized replicate counts, and render the three new figure families. The saved native-row map prevents signal being assigned to the wrong locus.

    scripts/plot_developmental_responses.R · runs before Step 05, independently of joint eligibility.

  6. Render standalone same-mark figures

    After the developmental response stage, reuse its completed tables and row-z signals to produce separate frequency, heatmap and scatter figures for each mark and gain/loss cohort. This adds outputs without replacing cross-mark developmental or joint-state figures, and does not refit statistics.

    scripts/plot_developmental_same_mark.R · runs automatically before Step 05.

  7. Summarize joint states and prepare locus review

    Combine H2AZ/H2AZac/H2AZub calls into three-symbol states. Count eligible changed states, draw joint-state plots, export state BEDs, and rank changed loci for manual review. Complete per-locus records remain available, including 000.

    scripts/05_joint_states.R through scripts/07_review_loci.R

4 · RunbookPrepare once, then run from the repository root

Use a Linux/macOS shell and conda. Commands below assume your terminal is inside h2az_joint_states/, the directory containing run_pipeline.sh. Opening this HTML file does not execute analysis commands.

1. Set up the isolated environments

bash setup_r_dependencies.sh
bash setup_peak_tools.sh

The R environment includes DiffBind, DESeq2, GenomicRanges, Rsamtools, csaw and ggplot2. The peak-tools setup provides external peak-calling tools. Existing peak files avoid those peak-calling dependencies during a run. Prefer isolation rather than upgrading a shared system R library.

2. Fill config/samples.csv

The shipped sheet is header-only; add real libraries before running. Use this exact minimal column order:

sample_id,include,mark,stage,genotype,sex,layout,bam,peaks,igg_bam,spikein_bam,bigwig
  • include: TRUE or FALSE. Marks: H2AZ, H2AZac, H2AZub. Stages: early, late. Genotypes: control, cKO. Layout: PE or SE, identical within each mark.
  • One row per animal per mark; merge technical runs first. Sample IDs must be unique and match [A-Za-z][A-Za-z0-9_]*. Supply indexed mm10 BAMs with chr chromosome names and consistent filtering.
  • File paths must be readable from the repository root. Supply peaks to reuse peak calls, or leave it empty to call peaks. bigwig is for visualization, not the statistical input.
  • igg_bam supplies an IgG control for peak calling; any supplied path must exist. It may be empty for the supported no-IgG calling modes. spikein_bam must contain an existing calibration BAM path for every included row when using spike-in normalization; it may be empty under background normalization.
  • animal_id and batch are independently optional. If supplied, insert them after genotype and before sex, with animal_id before batch when both exist. Every included row must have a value in each supplied optional column. To omit one, remove the column rather than leaving empty cells.
  • Supplied animal IDs must be unique within each mark but can repeat across marks. Omitting IDs does not remove the biological-independence requirement. Include batch metadata when batch adjustment is needed; deleting it does not fix confounding.

3. Check settings and normalization

Review config/settings.R. Keep NORMALIZATION <- "background" for relative enrichment. Use "spikein" only with validated, comparable calibration BAMs for every included library. Check the bundled mm10 blacklist path and available worker resources.

4. Run the full pipeline

H2AZ_USE_CONDA_R=1 bash run_pipeline.sh

This explicitly selects the isolated R environment and its libraries. Without H2AZ_USE_CONDA_R=1, the runner uses the caller’s Rscript unless explicitly overridden. It stops on the first failure; reruns overwrite fixed output names.

Keep results and settings together. Archive a completed run before changing inputs or settings. A successful self-test proves software behavior, not that your biological dataset or normalization is appropriate.

5. Re-render only the developmental figures

Use completed, mutually consistent Steps 01, 03 and 04 outputs for all three marks: validated inventory, master RDS, result TSVs, DDS objects, row maps and normalization tables. This does not refit statistics or read BAMs.

H2AZ_USE_CONDA_R=1
source config/tools.sh
"$H2AZ_RSCRIPT" scripts/plot_developmental_responses.R

The saved normalization mode must match config/settings.R. Changing the label alone does not renormalize results: restore matching settings or rerun Step 04. Heatmaps are written only as compiled multipage PDFs; legacy per-page heatmap PNG and SVG files owned by the rendered view are removed on rerun.

To rerender only the standalone same-mark figures after the developmental response stage has completed, use its saved tables and row-z signals together with the inventory and normalization metadata:

H2AZ_USE_CONDA_R=1
source config/tools.sh
"$H2AZ_RSCRIPT" scripts/plot_developmental_same_mark.R

To add all-peak views, set H2AZ_DEVELOPMENTAL_ALL_PEAKS=1 for both commands or the pipeline runner. Run the response stage first. Outputs go in each stage's all_peaks/ directory; the default gain/loss views are still produced. Unset or 0 skips the optional views without deleting previous optional outputs.

5 · Figure readingFrequency, signal and effect size answer different questions

Response-frequency bars: how often is a change detected?

Each anchor-mark figure has gain/loss rows, response-mark columns and early/late bars. Increased, decreased and no-detected-change segments sum to 100% of the testable cohort. Labels retain the original cohort size and the number untestable for that mark and stage.

Response % = 100 × loci in a response state / testable cohort loci

Illustration only: for five developmental-gain loci with late states +, -, 0, 0, N, four are testable: 25% increased, 25% decreased and 50% no detected change; one is untestable. This is an arithmetic example, not a result from your samples.

A locus remains counted if its response is 0, even when all three marks show no detected cKO change. A different mark or stage being untestable does not exclude it. If there are no testable loci, percentages are NA, with an explanatory panel instead of a fabricated bar.

Replicate heatmaps: what do the four-group profiles look like?

Colors are row z-scores of log2(normalized count + 1) across all included samples of the displayed mark. They reveal a locus’s relative profile, not its absolute enrichment compared with another locus or antibody. Constant rows have z = 0; display colors are clipped to ±3 while exported values are not.

Every gain/loss locus is retained. Rows sort by the anchor mark’s late cKO state, then descending absolute developmental LFC and locus ID. The row order and chunks of at most 500 are shared across response marks. Sample columns read EC, LC, EK, LK; the underlying exported matrices retain validated sample order. Normalized counts are not batch-corrected, even when the statistical model includes batch.

Effect scatterplots: which directions and magnitudes occur?

The horizontal axis is the anchor mark’s control-development LFC. The vertical axis is the response mark’s late-cKO LFC. Color denotes late response state; upward triangle, downward triangle, circle and cross denote positive, negative, no-detected and untestable interaction calls, respectively.

Only nonfinite x/y estimates are omitted. A finite estimate with state N stays visible as untestable. Panel annotations report exclusions and interaction calls. These plots are descriptive; the pipeline does not fit a reversal regression or test a correlation.

In the optional all-peak view, every master locus in the developmental comparison is included. Scatter colors show detected significance in the developmental and late cKO comparisons; shapes show which comparisons are untestable. Untestable does not mean established nonsignificant. Response frequencies exclude only response-untestable calls from their denominators.

Existing joint-state figures: what combinations change?

Read three-symbol codes in H2AZ / H2AZac / H2AZub order. For example, +0- means increased total H2AZ, no detected H2AZac change and decreased H2AZub in that contrast. It does not measure modification fractions. State strings in the TSVs use the ASCII hyphen -, not a typographic minus sign.

Do not mix the denominators. Joint-state primary panels share loci testable in all three marks across all four primary contrasts, then exclude 000 separately in each contrast. Their percentages are among changed loci. The interaction has its own jointly testable set. Developmental-response bars instead retain no-change responses within the selected cohort and use mark/stage-specific testability.

7 · BiologySeparate the observed association from its mechanism

What this analysis can tell us

  • Which loci show detected developmental gains or losses in control H2AZ, H2AZac or H2AZub signal.
  • Within those selected loci, how frequently Bap1 cKO is associated with increased, decreased or no detected signal change at each stage, among loci that can be tested.
  • Whether other marks change at the same developmental loci—for example, the H2AZac response at loci selected for normal H2AZub gain.
  • Which loci have interaction-supported differences in developmental trajectories and merit four-group inspection.

An altered endpoint is not necessarily an altered trajectory

A late cKO decrease at a normal developmental-gain locus opposes the normal direction, but does not alone show failed acquisition. A negative interaction means the cKO early-to-late change is less positive or more negative than the control change on the modeled log scale. That can arise from elevated early cKO signal, reduced late cKO signal, or both. In a loss cohort, it can mean a larger-magnitude developmental decrease, not a smaller change. Look at all four groups and replicate consistency before describing the pattern.

Significant development in controls and nonsignificant development in cKO is not itself a significant difference between trajectories. Use the interaction result for that question. Likewise, no detected interaction does not prove the trajectories are identical.

The selection caveat is central, not a footnote. Developmental cohorts are selected with control EC and LC. Same-mark early, late and interaction comparisons reuse those controls. Selection noise can favor early cKO increases, late decreases and negative interactions in gain cohorts (the reverse in loss cohorts). Control heatmap trajectories are selected by construction, and same-mark scatter axes share LC. Apparent reversal is therefore not independent evidence that Bap1 loss reverses development.

Cross-mark comparisons avoid reusing the same antibody-library measurements but may share animals or biological variation. Frequencies are descriptive and conditional on the selected cohort, sample size, testability and thresholds—not an independently validated estimate of Bap1 dependence or a formal enrichment test against other loci.

Boundaries on the claim

  • Relative, not absolute: background normalization supports relative enrichment changes, not genome-wide absolute gain or loss. Spike-in interpretation requires valid calibration.
  • Enrichment, not stoichiometry: H2AZac/H2AZub changes may accompany total H2AZ changes. Compare total H2AZ, but do not read these assays as percent acetylation/ubiquitination or divide antibody signals into a calibrated fraction.
  • Association, not direct action: the pipeline does not establish BAP1 binding, direct regulation, a catalytic substrate, or a causal molecular mechanism.
  • Locus, not gene function: no gene assignment, expression integration or pathway enrichment is implemented here. A changed chromatin locus does not itself establish altered transcription.
  • Detected cohort, not all genomic sites: the universe is the replicate-supported master regions, not every base in the genome. Cohorts from different anchor marks overlap.

A defensible result sentence

Report the anchor mark, developmental direction, original cohort size, tested count, response mark, stage, response direction and normalization. For example: “Among control developmental-gain loci for H2AZub, n of T loci testable for late H2AZac response showed decreased relative enrichment in Bap1 cKO; U cohort loci were untestable. This is a descriptive, control-selected comparison.” Replace the symbols with your actual exported values.

Then inspect master_regions.bed, relevant state BEDs, replicate bigWigs and the widest regions in IGV. The developmental response table supplies locus IDs for manual inspection; the new stage does not export developmental-cohort BEDs. Visual agreement and biological interpretation still require the lab’s actual data.

8 · ChecksBefore trusting a figure

  • Confirm every mark has all four groups and genuine biological replication; inspect sample labels and batch/group balance.
  • Review MA plots, normalization metadata, region support/width summaries and representative replicate tracks. These checks are not replaced by passing software tests.
  • For a percentage, read cohort_total, testable and untestable together; verify whether the figure uses a developmental or changed-joint-state denominator.
  • Check effect size as well as significance, since the calling rule has no fold-change cutoff.
  • For a developmental narrative, inspect all four groups, the interaction and the control-selection caveat.
The inventory fails before analysis

Read the reported sample IDs and missing fields/paths. Check exact header order, BAM indexes, permitted group values and minimum replication. All-empty optional columns are errors: remove a genuinely unused optional column or populate it correctly. Do not remove a required group to bypass validation.

The figure step reports normalization or identity mismatches

Use the DDS, result table, row map, master regions and inventory from the same run. Restore settings matching the saved normalization, or rerun upstream analysis intentionally. Do not reorder tables or relabel normalization to silence an error.

A developmental cohort is empty

This is a valid outcome: the step writes zero counts, NA percentages and annotated empty panels. It is not a reason to silently relax significance thresholds. An all-untestable response is different from an empty cohort; read the original total and excluded count.

Step 05 stops even though developmental figures were produced

The joint branch requires jointly testable loci and stops if its required shared sets are empty. The developmental step runs first and uses response-specific testability, so its completed outputs can exist even when Step 05 fails. The full runner still exits unsuccessfully; inspect the reported eligibility problem rather than calling the entire run complete.

Run the software checks directly

H2AZ_USE_CONDA_R=1
source config/tools.sh
"$H2AZ_RSCRIPT" tests/selftest.R
"$H2AZ_RSCRIPT" tests/inventory_selftest.R
"$H2AZ_RSCRIPT" tests/developmental_figures_selftest.R

Verification of the new step used saved synthetic DESeq2 objects with permuted native rows, size/per-locus normalization factors, empty cohorts and 500 + 1 heatmap pagination. Tests checked denominators and known locus/sample values; rendered PNGs and rerun/error behavior were inspected. That is execution evidence, not validation of biological conclusions.
